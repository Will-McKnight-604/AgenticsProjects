PROBLEM:
  PyOpenMagnetics API pipeline failed with exit code 1 when user ran 
  topology_wizard and clicked "Compute Requirements"

ROOT CAUSE:
  MAS JSON from build_mas_structure.m used field names (switchingFrequency)
  that didn't match what generate_om_recommendations.py expected (frequency_hz)

SOLUTION:
  Added transformation layer in call_pyopenmagnetics_api.py to bridge the gap

FILES CHANGED:
  1. call_pyopenmagnetics_api.py (NEW - 362 lines)
     - Added transform_mas_operating_points() function
     - Converts MAS field names to API field names
     - Provides default duty=0.4 and placeholder windings
  
  2. topology_wizard.m (MODIFIED - ~40 lines added)
     - Enhanced ImportError detection in results JSON
     - Added API error propagation to user
     - Improved results count extraction

COMMIT:
  Branch: topologyWizard_improve
  Hash: 75ebc8c
  Message: fix(api-pipeline): Debug and fix PyOpenMagnetics advisor API integration

FIELD TRANSFORMATIONS:
  Input (MAS)              Output (API)           Notes
  ==================       =================      ================
  switchingFrequency  -->  frequency_hz          Direct mapping
  ambientTemperature  -->  ambient_temperature   Rename only
  (not provided)      -->  duty                  Default: 0.4
  (not provided)      -->  windings              Default: Primary+Secondary
  (dropped)               outputVoltages
  (dropped)               outputCurrents

VERIFICATION:
  The transformation was tested and produces correct output:
  
  Input:  {switchingFrequency: 200000, ambientTemperature: 25}
  Output: {frequency_hz: 200000, ambient_temperature: 25, duty: 0.4, 
           windings: [Primary, Secondary]}

FALLBACK BEHAVIOR:

  1. First attempt fails with ImportError
  2. Error detected in results JSON (NEW - previously missed)
