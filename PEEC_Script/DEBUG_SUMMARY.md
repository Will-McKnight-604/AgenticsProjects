# API Pipeline Debug Summary

**Status**: RESOLVED ✓
**Commit**: `75ebc8c` - fix(api-pipeline): Debug and fix PyOpenMagnetics advisor API integration

## Executive Summary

The PyOpenMagnetics API pipeline was failing because the MAS JSON format generated by `build_mas_structure.m` didn't match the format expected by `generate_om_recommendations.py`. A transformation layer was added to `call_pyopenmagnetics_api.py` to bridge this gap, and error handling was improved in `topology_wizard.m`.

## Problem Statement

When users ran `topology_wizard` and clicked "Compute Requirements", the pipeline failed:

```
[API] Adviser error: generate_om_recommendations.py failed with exit code 1
```

The error was typically caused by:
1. **ImportError**: Python 3.12 (bundled with Octave 10.3.0) doesn't have PyOpenMagnetics
2. **Format Mismatch**: The MAS JSON fields didn't match what the recommendation script expected

## Root Cause Analysis

### Issue 1: Field Name Mismatch

**What MAS format provides** (from `build_mas_structure.m`):
```json
{
  "inputs": {
    "operatingPoints": [
      {
        "switchingFrequency": 200000,
        "ambientTemperature": 25,
        "outputVoltages": 5,
        "outputCurrents": 5
      }
    ]
  }
}
```

**What generate_om_recommendations.py expects**:
```python
config = {
  "operating_points": [
    {
      "frequency_hz": 200000,
      "ambient_temperature": 25,
      "duty": 0.4,  # MISSING - had no default
      "windings": [...]  # MISSING - no placeholder provided
    }
  ]
}
```

**The Mismatch**:
- `switchingFrequency` → `frequency_hz`
- `ambientTemperature` → `ambient_temperature`
- Missing: `duty` parameter
- Missing: `windings` array (required for excitation building in `_build_excitations_for_op()`)
- Nested structure: `inputs.operatingPoints` vs flat `operatingPoints`

### Issue 2: Import Error Handling

The fallback chain in `topology_wizard.m` (lines 1513-1547) attempted to detect ImportError but:
- Couldn't find the error message in stderr (it was written to the results JSON file instead)
- Didn't check the results JSON for API errors
- Made it impossible for the fallback chain to activate correctly

## Solutions Implemented

### Solution 1: Add Transformation Layer

**File**: `call_pyopenmagnetics_api.py` (NEW)

Created `transform_mas_operating_points()` function that:
1. Extracts `switchingFrequency` and renames to `frequency_hz`
2. Extracts `ambientTemperature` and renames to `ambient_temperature`
3. Provides default `duty = 0.4` (standard for forward converters)
4. Creates placeholder `windings` array with:
   - Primary winding: rectangular, 1.0A peak, 0.5A offset
   - Secondary winding: rectangular, 1.0A peak, 0A offset

**Before (line 122 of call_pyopenmagnetics_api.py)**:
```python
config = {
    "operating_points": mas_inputs['inputs']['operatingPoints'],  # Wrong format!
}
```

**After**:
```python
transformed_op_points = transform_mas_operating_points(mas_inputs['inputs']['operatingPoints'])
config = {
    "operating_points": transformed_op_points,  # Correct format
}
```

### Solution 2: Improve Error Detection

**File**: `topology_wizard.m` (lines 1513-1536)

Enhanced PyOpenMagnetics import error detection:

```matlab
% Also check if results file contains an ImportError (written by Python script)
if status ~= 0 && exist(results_file, 'file')
    try
        fid_check = fopen(results_file, 'r', 'n', 'UTF-8');
        raw_check = fread(fid_check, '*char')';
        fclose(fid_check);
        results_check = jsondecode(raw_check);
        if isfield(results_check, 'stderr') && ~isempty(strfind(results_check.stderr, 'ImportError'))
            is_module_error = true;
        end
    catch
        % Ignore errors during preliminary check
    end
end
```

This enables the fallback chain to properly detect ImportError even when it's written to the JSON file.

### Solution 3: API Error Propagation

**File**: `topology_wizard.m` (lines 1573-1576)

Added explicit check for API errors and propagate to user:

```matlab
% Check for API errors in results
if isfield(results, 'status') && strcmp(results.status, 'ERROR')
    error('PyOpenMagnetics API error: %s', results.error);
end
```

## Key Design Decisions

1. **Default Duty = 0.4**: This is the standard nominal duty cycle for forward converters. Used as fallback when topology_wizard doesn't compute explicit duty.

2. **Placeholder Waveforms**: Without topology-specific waveform data, use default rectangular waveforms with 1.0A amplitude. These provide a baseline for the adviser to compute recommendations.

3. **Transformation in call_pyopenmagnetics_api.py**: This layer bridges the MAS format (from MATLAB) to the legacy recommendation script format (generate_om_recommendations.py), allowing both to coexist without modifying either.

4. **Results JSON Error Detection**: Rather than relying on stderr parsing, check the actual output JSON for error messages. This is more robust when Python writes errors to the file.

## Future Improvements

1. **Topology-Aware Duty**: Pass topology-specific duty cycle from topology calculator when available
2. **Topology-Aware Waveforms**: Use correct waveform shapes (triangular for buck/boost, rectangular for forward, etc.)
3. **Direct MAS API**: When PyOpenMagnetics adviser API stabilizes, replace subprocess delegation with direct Python calls
4. **Multi-Output Support**: When topology wizard supports N outputs, pass all output specifications in winding array
