TOPOLOGY METADATA SYSTEM - QUICK VERIFICATION
================================================

Files Created:
1. topology_metadata.m - Main registry (14KB)
2. get_topology_metadata.m - Get topology definition
3. get_field_metadata.m - Get field definition
4. is_field_required.m - Check if field required
5. get_visible_fields_for_topology.m - Get all fields for topology
6. get_topology_output_type.m - Get output type (single/multi)

Key Features:
- 9 topologies supported (two/single/active-clamp forward, flyback, push-pull, buck, boost, isolated-buck, isolated-buck-boost)
- Field metadata with labels, units, ranges, defaults, MAS paths
- Error handling for invalid topology/field names
- Persistent caching for performance
- Consistent field naming (snake_case with indexed outputs _0, _1, _2, _3)

Topology Output Types:
- Single-output: buck, boost
- Multi-output: all others (forward variants, flyback, push-pull, isolated variants)

Field Categories:
1. Input voltage (minimum, maximum, nominal)
2. Output voltage/current (indexed _0, _1, _2, _3)
3. Single output (voltage, current - for buck/boost)
4. Control (switching frequency, duty cycle)
5. Component losses (diode voltage drop)
6. Constraints (current ripple, max switch current, max drain-source voltage)
7. Performance (efficiency)

MAS Path Mapping:
- inputs.designRequirements.* - Design requirements
- inputs.operatingPoints(1).* - Operating points
- Nested structures: .minimum/.maximum/.nominal

Data Types:
- All numeric fields with min/max ranges
- Optional fields marked with optional=true, default=[]
- Default values set appropriately per field

Caching Strategy:
- Persistent variables in getter functions
- Single initialization on first call
- topology_metadata() called once per process
